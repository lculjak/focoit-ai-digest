# CLAUDE.md — focoit-ai-digest

Project conventions and the AI-engineering setup for this repo. Read this first.

## What this is

A self-contained **static site** (GitHub Pages) that publishes a weekly, Focoit-lens AI/cloud digest.
The page and its data are **generated by an agentic gh-aw workflow** (`engine: claude`) and land via a
human-gated pull request. There is **no build step** for the site — `docs/index.html` is a single
self-contained HTML5 file.

## Confidentiality tier — NON-SENSITIVE / PERSONAL

Public repo, Focoit's own content, no client/proprietary code, no secrets in the tree
(`ANTHROPIC_API_KEY` lives in Actions secrets). The full hybrid flow — including hosted agentic CI —
is allowed. See [policies/model-execution-policy.md](policies/model-execution-policy.md).

## Commands / gates

- **Repo gate (deterministic):** `pwsh -NoProfile -File scripts/validate-repository.ps1 -All`
  (PASS = 0 blocking, 0 warnings). Runs automatically on commit via the pre-commit hook.
- **Install hooks (once per clone):** `pwsh -NoProfile -File scripts/setup-hooks.ps1`
- **Workflow gate:** for any change under `.github/workflows/weekly-ai-digest.md`, run
  `gh aw compile` (0 errors / 0 warnings) and commit the `.md` **+** `.lock.yml` **+**
  `.github/aw/actions-lock.json` together. The deterministic guardian does NOT validate the workflow —
  `gh aw compile` is that gate.
- **Site check:** open `docs/index.html`; confirm theme, search, filters, mobile layout, and that
  cards link out.
- **No unit tests / no build** for the static site.

## Conventions

- **`docs/` is agent-owned output.** `index.html` and `docs/data/*.json` are regenerated weekly by
  the workflow — don't hand-edit them except for deliberate template/structure changes (which the
  agent's prompt must then be taught to preserve).
- **Secrets never in files.** Ever. The guardian's secret scan is a hard block; keep it that way.
- **gh-aw is experimental** — pin the extension version; recompile after upgrades; keep the
  `.lock.yml` committed so runs are reproducible.

## The dogfooding loop (how work gets done here)

Four-tier flow (this repo is non-sensitive, so all tiers are available):

1. **Plan (Claude)** — only for complex/architectural items (the workflow design, curation logic,
   safety review). Skip for routine one-file edits.
2. **Execute (Cline FREE / Aider, or Copilot Pro)** — routine HTML/CSS/JS/docs/JSON edits.
3. **Review (Copilot Pro)** — independent, advisory. Prefer a **local pre-commit** review pass so
   fixes land in the same commit; the online PR auto-reviewer is an optional second opinion.
4. **Deterministic final check** — `validate-repository.ps1 -All` + `git diff` scope check → commit
   (never `--no-verify`) → push → update the backlog.

Routing detail: [policies/ai-routing-policy.md](policies/ai-routing-policy.md).

- **Backlog:** [roadmap/pending-improvements.md](roadmap/pending-improvements.md) — one item (or a
  tight slice) per commit, with a Status + Revision trail.
- **As-run prompt provenance:** save the prompts you actually sent (executor / reviewer / revision)
  to `roadmap/prompts/<item-id>.md` — or a folder for multi-artifact items — marked frozen / not
  maintained. Audit trail (item → prompts → commit), distinct from any reusable template.
